# 2D→3D 自动生成：纪要需求理解与刷新方案

依据《三维自动生成规则制定与VMB试点_20260805》客户纪要，重述核心需求，对照当前实现，给出刷新方案。

## 一、纪要确定的核心规则

1. **以点料表为最全基准**
   - 点料表信息最全（2D图可能缺），三维模型的**物料与数量以点料表为准**。
   - 2D 图只用来**摆位置**（定位）。

2. **匹配基准 = U9码**
   - 以点料表 U9码 作为物料唯一识别键，U9码 ↔ 三维器件库模型对应。
   - 多对一（多个 U9 对应同一模型）允许；只要一个 U9 对应一个器件即可。

3. **输入三件套**：学习阶段 = 2D + 点料表 + 三维器件库；使用阶段 = 2D + 点料表 + 统一器件库，输出 3D。
   - 器件库统一，跨项目复用，供学习/匹配。

4. **三维与点料表 1:1 对应、可核对**
   - 生成结果里的每个物料都能对应回点料表某条（U9码）。
   - **未匹配的物料要标红/列出**，便于客户检查哪些 U9 没配上。

5. **先做 VMB 简化验证**：改点料表→生成3D→与点料表一一对上，即证明机制可行。

## 二、当前实现与需求的差距

| 纪要要求 | 当前实现 | 差距 |
|---|---|---|
| 以点料表为最全基准，三维物料=点料表全部 | 三维从 **match_result.components（=PID组件）** 出发，只生成2D图里出现的组件 | **范式相逆**：当前以2D为主，点料表只作辅助；纪要要求以点料表为主 |
| 匹配基准=U9码 | matcher 用 `_score_match`（名称/管径/类型）**模糊打分** | **完全未用U9码**，易错配 |
| 未匹配物料标红提示（按U9码） | 前端有"未匹配组件"列表，但语义是PID组件未匹配，非U9维度 | 需改为按点料表U9维度列出未匹配器件 |
| 器件库↔点料表映射 | 器件库只有型号名(PLPV-K08)，无U9码 | **缺 U9↔型号 桥接**，需建立映射 |

## 三、刷新方案

### 核心范式转变：从"2D组件驱动"改为"点料表BOM驱动"
1. **三维物料清单 = 点料表全部有U9码的物料**
   - 生成阶段改为遍历 BOM 物料（而非PID组件），每个有 U9 码的物料放一个器件实例。
2. **建立 U9码 → 三维器件模型 映射表**
   - 数据来源：点料表每条物料 → 其 spec 里的型号代码（如 PLPV-K08）→ 器件库 STP 按型号匹配。
   - 支持多对一（多个U9 → 同一型号模型）；生成映射表 `u9_model_map.json`，学习时自动构建。
3. **匹配引擎重写（matcher.py）**
   - 从"按PID组件名称模糊打分"改为"以 U9码 为键，BOM→器件模型 直接1:1映射"。
   - 2D PID 组件仅用于确定器件摆放位置（若该U9在2D有对应组件则用其坐标，否则自动排布）。
4. **未匹配标红**
   - 前端/结果里按 U9码 列出"点料表有但器件库没有对应模型"的物料，标红提示。
5. **VMB 试点验证**
   - 用 8A 点料表（139条，全有U9）实测：生成的三维应包含139种物料（去重后若干器件），并逐一可与点料表U9对上。

## 四、改动文件
- `modules/matcher.py`：匹配逻辑改为 U9码1:1 + 器件映射
- `modules/learning_engine.py`：学习阶段构建 U9→型号→器件 映射表
- `modules/model_generator.py`：生成阶段以BOM驱动，2D辅助定位
- `templates/index.html`：未匹配按U9标红提示
- `app.py`：打通 U9映射表的保存/加载

## 五、待确认前提
- U9码↔器件型号的桥接：先用现有数据（点料表spec型号代码 + 器件库STP型号名）自动建立，部分缺件需人工补。
- 三维器件摆放：有2D坐标的用2D坐标；无的（点料表独有物料）用自动网格排布。
